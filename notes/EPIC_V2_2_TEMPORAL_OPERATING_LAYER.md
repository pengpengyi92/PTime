# EPIC Note — PTime V2.2 Temporal Operating Layer

Date: 2026-09-25

## Core idea

PTime should evolve from:

Timezone Adapter
-> Global Communication Timing Layer
-> Relationship Timing Layer
-> **Temporal Operating Layer**

Its job is to make limited time more effective.

## Core question

Not merely:

"What time is it in London / New York?"

But:

"What should become actionable now because of time?"

## Collaboration map

- **PWeb / PCV**: materials, self-introduction, CV, portfolio, websites, artifacts.
- **PCT / PRT**: career information, recruiting pipeline, opportunity state, interviews.
- **PConnection / PGlobal**: people and geography.
- **PREST**: recovery, rest, sustainable pacing.
- **PTime**: timing, ordering, cadence, windows, deferral, next action.

## Execution objects

PTime can manage:
- connect
- reconnect
- follow-up
- greeting
- interview
- meetup
- arrangement
- material send
- progress update
- reminder
- opportunity window
- recovery window

## Temporal pipeline

Signal
-> timing trigger
-> relevant person / opportunity
-> required material
-> best channel
-> action window
-> human approval
-> execution
-> next follow-up time.

Signals can include:
- timezone opening;
- elapsed follow-up interval;
- festival;
- reply received;
- meeting scheduled;
- interview deadline;
- application status change;
- artifact ready;
- travel / location change;
- rest requirement.

## North Star

**Make every unit of time more effective while expanding global reach.**

PTime should increase:
- execution density;
- global connectivity;
- follow-up reliability;
- interview / meetup conversion;
- material reuse;
- opportunity continuity.

It should reduce:
- missed follow-ups;
- poor-timing outreach;
- unnecessary context switching;
- idle waiting;
- duplicated communication;
- work that should have been deferred.

## Design principle

PTime is not a system for filling every minute.

Efficient time management includes:
- knowing when to act;
- knowing what to postpone;
- knowing when another region becomes available;
- knowing when a follow-up is due;
- knowing when rest is the highest-value action.

## Long-run abstraction

Other systems answer:
- WHO
- WHERE
- WHAT
- WHY
- HOW

PTime specializes in:
- **WHEN**
- **WHAT NEXT**
- **WHEN NEXT**

That makes PTime the temporal coordination layer across the wider system.
