# EPIC — Same-Timezone Location-Independent Connection Infrastructure

Date: 2026-09-26

## Why this is EPIC

This discussion creates a cross-system abstraction rather than a single location note.

The key transformation is:

**physical location can change without breaking global execution, as long as the time layer remains stable.**

China mainland cities share UTC+8. Therefore Shenzhen, Zhongshan, Shanghai, Beijing, Hangzhou and other China nodes can run on one PTime schedule while exposing different local affordances through PMap.

This connects four previously separable systems into one operating loop:

**PTime + PGlobal + PLinkedIn + PConnection**

The loop is:

1. PTime detects active global talk zones.
2. PGlobal maps those zones to target markets / institutions / communities.
3. PLinkedIn finds or activates relevant people.
4. PConnection stores relationship state, DD history and follow-up.
5. Informal talk converts timing overlap into real knowledge, trust and opportunities.

## Zhongshan Transformation

Zhongshan becomes more than a rest destination.

It is a **high-comfort remote relationship-building node**:
- life logistics are low-friction;
- recovery quality is high;
- family / food / housing / walking support attention recovery;
- remote meetings remain fully executable;
- visitors can be hosted for informal conversation, walking and relaxed relationship building.

This means recovery and execution are not opposites.

**Recovery infrastructure can increase the quality of global execution.**

## Operating Model

- Shenzhen: high-density physical execution node.
- Zhongshan: high-comfort recovery + informal-talk node.
- Both: same PTime / UTC+8 global communication engine.

The city changes the local mode, not the global clock.

## North-Star Principle

**Location-independent connection, timezone-aware execution, city-specific affordances.**
