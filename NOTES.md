# Location-Independent Execution

## Principle
**Execution Base != Physical Base.**

Execution should not be coupled to one city, office, or fixed work location. If network access, devices, materials, and time-zone coordination are available, communication and knowledge work can continue from home, during travel, or from another city/country.

## What remains executable remotely
- informal meetings / talks
- due diligence
- CV and material sending
- follow-ups and relationship communication
- interview preparation
- research
- engineering

## Travel x Execution
Travel changes where execution happens, not whether execution happens.

A trip can combine:
1. relaxation / exploration,
2. PMF / PMap observation,
3. PTime-based communication windows,
4. PGlobal informal talks and due diligence,
5. remote research / engineering.

Examples:
- Zhongshan -> Shenzhen / Hong Kong remote conversations
- Reading -> London informal meetings and talks
- Thailand or another travel destination -> Asia / Europe / US communication routed by local time

## Operating rule
Do not require returning to a specific physical base before starting execution. When travelling or at home, identify one communication close and one research/engineering close that can be completed remotely.

## System implication
- **PTime**: current physical location becomes an input to time-zone routing.
- **PGlobal**: global connection execution remains available independent of physical base.
- **PMF / PMap**: travel can coexist with execution instead of pausing it.

> Travel changes where we execute, not whether we execute.

# Relationship Timing Layer

## Principle
**PTime = Timezone Adapter + Relationship Timing Layer.**

PTime should help decide not only *what time it is elsewhere*, but also *when to connect, reconnect, follow up, interview, or send a lightweight greeting*.

## Core responsibilities
- Connect people at the right time.
- Arrange and prepare interview timing across time zones.
- Manage daily follow-up cadence.
- Surface natural reconnect windows.
- Use festivals and milestones as lightweight relationship-maintenance triggers.
- Route communication through the appropriate channel: WeChat, LinkedIn, email, calendar, or other connected systems.

## Relationship rhythm
**Greeting = maintenance.  
Follow-up = progress.  
Meeting / interview = conversion.  
Artifact / progress update = value creation.**

A festival greeting is useful because it is low-friction and natural, but it should not replace daily work. Durable relationships are built by consistent follow-up, concrete progress, useful questions, meetings, and shared artifacts.

## Timing pipeline
Festival / milestone / elapsed time / reply / timezone opening
-> identify relevant contact
-> choose communication intent
-> choose channel
-> human-approved message
-> send
-> record response
-> schedule next follow-up
-> meeting / interview / collaboration when appropriate.

## Operating principle
Use PTime continuously. Good relationship management is not a once-a-year greeting task; it is an ongoing timing and follow-up system.
