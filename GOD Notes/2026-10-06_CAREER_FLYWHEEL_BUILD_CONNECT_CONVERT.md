# PTime GOD NOTE — Career Flywheel Time Allocation

**Date:** 2026-10-06

## Principle

Career progress should run as three parallel AlphaTime lanes:

```text
BUILD — PBCT
CONNECT — PACT
CONVERT — Official Process
```

Do not serialize them.

Bad pattern:

```text
network for weeks
→ then build
→ then eventually apply
```

Preferred pattern:

```text
Build today
+ talk today
+ apply/follow-up today
→ each lane improves the other two
```

## Time-block rule

Every career-related block should be tagged with one primary lane:

- **B — Build:** code / research / CV / proposal / case.
- **C — Connect:** informal talk / coffee / meal / meeting.
- **V — Convert:** application / email / interview / follow-up.

A block may produce secondary outputs in other lanes.

Example:

```text
18:30 informal dinner
Primary: C
Secondary: observation + local DD

20:30 capture notes
Primary: B
Output: PMAP + People Graph + role questions

21:00 official application update
Primary: V
Output: application / follow-up
```

## Close-driven rule

After a Connect block, spend a short capture block to record:

- what changed;
- what was learned;
- who/what is next;
- whether an official action follows.

After a Build block:
- identify the role/professor/application it strengthens.

After a Convert block:
- identify the next wait/follow-up/interview preparation action.

## Anti-drift

Informal social time is productive only when it supports:

- connection;
- observation;
- recovery;
- or an upcoming T+1.

If it becomes unbounded/no-purpose/no-capture, it is no longer AlphaTime.

## Career flywheel

```text
CONNECT
  ↓ context
BUILD
  ↓ evidence
CONVERT
  ↓ real feedback
CONNECT / BUILD again
```

Protect recovery and sleep so the next cycle starts with high energy.

> **Time is not divided between networking and building; time is designed so networking, building, and conversion compound.**
