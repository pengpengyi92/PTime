# PTime V2.1 Local Contract

## Ownership

PCV owns WHAT: `self_intro.zh-CN`, `self_intro.en`, optional role variants.
PTime owns WHEN. Reference-only assets use `communication_asset_type`:
`self_introduction`, `greeting`, `follow_up`, `thank_you`, `career_update`.
`asset_ref: pcv:self_intro.en` is an opaque string; PTime never opens another repo,
loads a CV, fetches a URL, drafts a private introduction, or sends a message.

## Snapshot

`private/touchpoints.yaml` (or explicit `--input` YAML/JSON) has exactly five lists:

```yaml
contacts: []
pending_actions: []
preferences: []
history: []
followups: []
```

Contacts and pending actions retain the [V2.0 contract](v2-contract.md).
All IDs refer to that contact registry. Maximum input 1 MB, 1,000 entries per list.
All history timestamps require numeric offsets or Z; future evidence is rejected.
No names, raw messages or conversation transcripts are required in the added lists.
No real snapshots or generated outputs may be committed to the public repository.

## Explicit Festival Applicability

```yaml
preferences:
  - contact_id: fictional-alumni
    festival_ids: [mid_autumn, new_year]
    excluded_festival_ids: []
    locale: zh-CN
    style: professional
    audience: alumni
    active_conversation: false
    recent_contact_hours: 72
    allow_active_conversation: false
    allow_recent_contact: false
    reset_cycles: []
```

Missing festival opt-in means SKIP, even for contacts in China, the US or the UK.
Region/calendar filters select events, not a person's identity or observance.
An exclusion wins over inclusion. Templates support general/professional/reconnect
and en/zh-CN without silent locale fallback. General audience copy is public-safe;
an explicit audience-specific template wins if configured.

Only the user may edit `allow_*` flags or add a canonical `festival_id:YYYY` to
`reset_cycles`. These are explicit manual frequency overrides, not command-line
mass-send controls. They cannot override do-not-contact, excluded festivals,
closed/declined history, terminal V2 queue actions, channel restrictions or rest.

## Greeting History

```yaml
history:
  - contact_id: fictional-alumni
    festival_id: mid_autumn
    cycle: 'mid_autumn:2026'
    template_id: mid_autumn.professional.zh-CN
    channel: wechat
    greeted_at: '2026-09-23T10:00:00+08:00'
    reply_state: replied
    replied_at: '2026-09-23T14:00:00+08:00'
    closed: false
```

The human records a send/reply after it actually happens. Merely rendering or
re-running recommendations writes nothing and does not change interaction state.
One greeting per contact/canonical festival cycle across all channels. Recent use
of the same template within 30 days is also suppressed unless the cycle is reset.
Old template IDs remain valid send evidence even after that template is retired.
Active conversations are suppressed by default. Recent-contact evidence includes
both sends and replies; date-only contact evidence conservatively uses end-of-day.

SUGGEST is advisory, never authorization. Output states include WAIT, SKIP,
BLOCKED, GREETED, REPLIED, FOLLOW_UP_ELIGIBLE and CLOSED. A denied channel never
falls back to an unlisted one. A holiday does not override professional weekends.

## Follow-up Timing

Replied history generates one stable `after:contact_id:cycle` advisory item.
No-reply history produces SKIP indefinitely unless the user supplies a separate
request. No auto-reminder, retries, scheduler or transport is present.

```yaml
followups:
  - id: planned-conversation
    contact_id: fictional-alumni
    cycle: 'mid_autumn:2026'
    channel: email
    status: pending
    not_before: '2026-09-25T09:00:00+08:00'
    due_at: '2026-10-01T18:00:00+08:00'
    reply_delay_hours: 24
    cooldown_hours: 168
    opportunity_urgency: 1
    communication_asset_type: follow_up
    asset_ref: pcv:self_intro.en
```

Alternatively, `user_requested_at` explicitly opens a new user-requested window;
a standalone request may omit cycle. An explicit cycle must have recorded history.
Defaults: at least 24 hours after reply, 7 days between prior follow-up attempts
or after an unanswered greeting, 30-day freshness limit for automatically using
an old reply. `last_followup_at` records an actual previous follow-up. Frequency
checks are contact-wide across request IDs/channels. Record completed/canceled
requests to suppress later automatic recommendations for the same cycle.

Relationship class, preferred windows and context flow through V2.0 policy.
Soft due dates and opportunity urgency order actionable results but cannot bypass
gates. Sender quiet hours are protected in the requested base timezone too.
Search is bounded to the policy horizon from the earliest admissible instant;
festival windows additionally expire. No joint window means no ready suggestion.

V2 terminal relationship-maintenance actions close greeting suggestions for that
contact; terminal follow-up actions close follow-up recommendations. Routing
also suppresses a new festival suggestion if a V2 maintenance draft is already queued.
Use that existing queue rather than creating another cross-channel draft.
The snapshot is a current action queue, not an eternal archive: manually retire historical
queue entries when opening a genuinely new cycle, without deleting send history.

## Calendar Configuration

Four packaged files in `config/festivals/` define named views, defaults, canonical
festival definitions and shared-ID includes. US/UK/China may include `new_year`
without creating multiple greeting cycles. `--region` chooses a declared view;
new region files can be added under a complete private configuration directory.

Supported date rules: Gregorian fixed month/day, nth weekday (1..4 or last), and
explicit year-to-date tables. Lunar festivals and UK variable/exception-prone
dates are sourced for **2026-2027 only**. Missing years emit UNKNOWN warnings;
there is no guessed lunar conversion or assumption that all UK divisions match.
UK default bank-holiday scope is England/Wales, not Scotland/Northern Ireland.

`official_holiday_period` is separate, inclusive, source/jurisdiction-tagged
metadata. It does not prove personal availability or modify working weekdays.
Missing periods are unknown, not proof of no holiday. Mainland makeup working
days, individual leave and full regional holiday calendars are NOT implemented.

`not_before` is local midnight on cultural date minus lead_days; `expires_at` is
local midnight on cultural date plus valid_window_days (exclusive). Recipient
timezone determines touchpoint boundaries; calendar listings use the chosen
view/default zone. Both DST offsets are respected. Rare invalid midnight walls
fail explicitly rather than fabricate an instant.

Calendar configuration is validated. No runtime network calls. See
[calendar sources](festival-sources.md). Non-greeting bank/memorial/civic holidays
remain visible with `--include-non-greeting`, but do not trigger greeting outreach.

## Scoring and Limitations

Eligible explicit-opt-in touchpoints use `0.8 * V2_score + 0.2`. V2 score includes
time/channel/priority/relationship/recency/opportunity factors. Decision state is
sorted before score. Region is a selected view, not an inferred personal trait.
Components/reasons are exposed. This is an uncalibrated heuristic, not a response
probability. Personal availability and relationship outcomes remain UNMEASURED.

CLI JSON uses schema 2.1 for the four new commands; existing now/contacts/talk/email
contracts remain unchanged. CLI returns no implicit example contacts unless --demo.
The demo is dated 2026-09-25; using earlier instants will reject future history.
