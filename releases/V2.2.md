# PTime V2.2 — Temporal Operating Layer

Status: PLANNED
Planned version: 2.2.0
Plan date: 2026-09-25

## Theme

Make time more effective.

PTime V2.2 expands from communication timing into a broader temporal operating layer for global execution.

The goal is not only to know when another region is awake.
The goal is to use limited time with higher execution density, better follow-up continuity, and broader global reach.

## North Star

**Make every unit of time more effective.**

Use timing to:
- connect globally;
- follow up consistently;
- arrange interviews and meetings efficiently;
- surface the right material at the right moment;
- coordinate career and opportunity execution;
- preserve time for rest and recovery when appropriate.

## Core timing actions

PTime V2.2 should support timing around:
- Connect
- Reconnect
- Follow-up
- Interview
- Meetup
- Greeting
- Arrangement
- Progress update
- Artifact / material delivery
- Reminder
- Opportunity window
- Rest / recovery window

## System collaborations

### PWeb + PCV — Material Layer
PWeb and PCV provide the materials that can be surfaced at the right time:
- profile
- self-introduction
- CV
- portfolio
- website
- research / engineering artifacts
- reusable communication materials

PTime answers WHEN those materials should be used.

### PCT + PRT — Career / Opportunity Layer
PCT and PRT provide:
- career targets
- recruiting pipelines
- opportunities
- interviews
- follow-ups
- due-diligence threads
- next actions

PTime turns those states into time-aware execution.

### PREST — Recovery / Energy Layer
PREST provides rest, recovery and sustainable rhythm constraints.

PTime should optimize execution density without turning every hour into outreach.

## Operating model

PWeb / PCV -> WHAT MATERIAL
PCT / PRT -> WHAT OPPORTUNITY
PConnection / PGlobal -> WHO / WHERE
PTime -> WHEN
Channel adapters -> HOW
Human -> DECISION / SEND / MEET

Combined:

WHO x WHERE x WHAT x WHEN x HOW -> ACTION

## Relationship timing

Greeting = maintenance.
Reconnect = reopen.
Follow-up = progress.
Meeting / interview = conversion.
Artifact / progress update = value creation.

Festival greetings remain one natural timing trigger, but V2.2 generalizes the pattern beyond festivals.

## Efficiency principle

PTime should continuously answer:

1. What is actionable now?
2. What is becoming actionable soon?
3. Which people are in a good communication window?
4. Which follow-ups are due?
5. Which interview / meetup windows should be arranged?
6. Which material should be prepared or sent before that window?
7. Which actions should be deferred?
8. When should work stop and recovery begin?

## Global execution principle

PTime should make one physical base compatible with global execution.

A user can work from one location while communicating with:
- Hong Kong / Singapore in Asia windows;
- London / Europe in Europe windows;
- New York / Boston in US East windows;
- San Francisco / US West in later windows.

Timezone routing is the foundation.
Temporal orchestration is the destination.

## Release dependency

V2.2 builds on the planned V2.1 festival timing layer.

V2.1 should establish reusable timing triggers and greeting / follow-up rules.
V2.2 should generalize those primitives into cross-system temporal orchestration.

## Release gate

Do not tag or mark CLOSED until:
- V2.1 prerequisites are resolved or intentionally folded into V2.2;
- temporal action model is implemented;
- material / opportunity adapters are defined;
- prioritization and deferral rules are tested;
- privacy and human-approval gates remain intact;
- all prior regression tests pass;
- docs and version metadata are consistent.

Until then, the canonical release remains the current VERSION value.
